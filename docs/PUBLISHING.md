# Публикация выпусков

## Предварительный выпуск 0.9.3

Текущий выпуск предназначен для обратной связи: arm64, macOS 14+, ad-hoc подпись, без нотарификации. Это явно указывается в README и заметках релиза. Не называйте его Developer ID-signed или Apple-notarized.

1. Проверьте версию в `Info.plist`, CHANGELOG и ручной чек-лист.
2. Соберите приложение из того же коммита, на который указывает тег выпуска: `bash build.sh`, затем `bash scripts/make-dmg.sh`.
3. Проверьте bundle и `hdiutil verify dist/MacPanel.dmg`.
4. Переименуйте файл в `MacPanel-v0.9.3-arm64.dmg`; рядом создайте `SHA256SUMS.txt` командой `shasum -a 256 MacPanel-v0.9.3-arm64.dmg > SHA256SUMS.txt`.
5. Опубликуйте тег `v0.9.3` и GitHub Release с отметкой **pre-release**. Приложите DMG и контрольную сумму. GitHub автоматически предоставляет архивы исходников по тегу.
6. В заметках укажите требования, установку перетаскиванием в «Программы», статус подписи, изменения и известные ограничения.
7. Проверьте скачивание обоих файлов со страницы релиза и контрольную сумму.

Исходники и пользовательские данные хранятся отдельно. Не публикуйте локальные логи с путями пользователя, `Application Support`, сертификаты, ключи, `.build` и прочие кэши. Бинарные файлы размещаются в Releases, а не в истории Git.

## CI

`.github/workflows/build.yml` собирает Apple Silicon приложение и тестовый DMG на macOS, проверяет подпись. Он не подтверждает UI-поведение и показания физических датчиков на всех Mac. GitHub Actions может требовать разрешения владельца аккаунта или расходовать доступную квоту.

## Будущий Developer ID + нотарифицированный выпуск

Существующий ручной workflow `.github/workflows/release.yml` предназначен для отдельно настроенной подписанной публикации. Для него необходимы сертификат Developer ID Application и доступ к App Store Connect API. По умолчанию workflow не запускается.

Настройте переменную `MACPANEL_BUNDLE_ID` с собственным reverse-DNS ID и секреты:

- `MACPANEL_DEVELOPER_ID`: точное имя подписи.
- `MACPANEL_DEVELOPER_ID_P12_BASE64`, `MACPANEL_DEVELOPER_ID_P12_PASSWORD`.
- `MACPANEL_CI_KEYCHAIN_PASSWORD`.
- `MACPANEL_ASC_API_KEY_P8`, `MACPANEL_ASC_API_KEY_ID`, `MACPANEL_ASC_ISSUER_ID`.

Используйте новый тег версии. Перед запуском сравните коммит сборки и тег, проверьте соответствие версии в Info.plist. Подписанный workflow ещё не был проверен с реальными сертификатами в этом проекте. После notarization и stapling проверьте Gatekeeper и чистую установку скачанного артефакта на другом Mac. Для локальной нотарификации уже подписанного образа доступен `scripts/notarize-dmg.sh` с `MACPANEL_NOTARY_PROFILE`.

Никогда не добавляйте сертификаты и ключи в исходники или заметки релиза.
